# AI Act Transparency Kit — три критика, 17.09.2026

Три независимых прохода по состоянию на утро 17.09: аудитор по AI Act, архитектор n8n, нанимающий менеджер
на роль AI & Automation Lead. Ниже сжатые выводы каждого и мой список правок с отметкой, что уже сделано.

## 1. Аудитор по AI Act

Ошибки против текста акта:
- **Дипфейк определён неверно** (ст. 3(60)): это контент, похожий на существующих людей, *объекты, места,
  события*, который кажется подлинным. Кит смотрит только на «реальный человек». Поддельное фото реального
  события без людей уходит как synthetic_media с меткой «по политике дома», хотя обязанность по 50(4) есть.
  Нет поля «сгенерировано или изменено», а метка всегда говорит «AI-generated».
- **Согласие подано как обязанность по ст. 50.** В акте согласия нет, это GDPR и право на образ. → сделано:
  вынесено в отдельный блок «Other law».
- **Неверные статьи у ворот, журнала, реестра.** Ст. 14 и 12 — обязанности провайдера высокорисковых систем;
  у деплоера это 26(2) и 26(6), тоже только для высокого риска. Ст. 4 не требует реестра. → сделано: блоки
  помечены «voluntary», ссылки на 14 и 12 убраны.
- **«Сторона деплоера по ст. 50» неполна.** Нет 50(3) — распознавание эмоций и биометрия. Чат-боты (50(1))
  сканер не видит как «взаимодействие с людьми». Художественное и сатирическое исключение не смоделировано.
- **Статус disclosed утверждается, не доказывается, и нарушает 50(5).** Для аудио кит пишет только метаданные,
  неслышимые слушателю, а страница печатала «visible label: yes». Реестр жёстко ставил disclosed всем
  внешним генераторам, из-за чего один и тот же актив был «returned» в блоке 2 и «disclosed» в блоке 1.
  → сделано: статус берётся из решения; колонка переименована в «Disclosure» и честно пишет «metadata +
  sentence at publication» для аудио.
- Вопрос приёма не содержит теста «по вопросу общественного интереса». → сделано.
- Редакторское исключение записывает имя, но не доказательство правки: нет диффа.
- Любой узел Wait считался воротами, включая таймер. → сделано: только resume = form или webhook.

Чего аудитор попросит и не увидит: аутентифицированную личность рецензента; защиту от подмены записей
(хеш-цепочка, append-only); историю реестра, а не пересборку; доказательство полноты, если API не ответил
(→ сделано: флаг registry_partial на странице); сам опубликованный артефакт и доказательство, что раскрытие
дошло до человека.

## 2. Архитектор n8n

- **R1, критично: инъекция в shell через публичную форму.** Расширение файла и поле Model попадали в команду
  ffmpeg. → сделано: расширение по белому списку на тип актива, всё пользовательское в shell проходит через
  фильтр символов.
- **R2: файловая система как база данных, один хост, без блокировок.** registry.json переписывается целиком
  на каждое решение, чтение манифестов порождает процесс node на файл, аудит-страница без авторизации и кэша.
- **R3: ссылки на ворота — bearer-токены, и они утекают** на страницу аудита без авторизации; поле Reviewer
  свободный текст. Это бьёт по главному, что продаёт кит: ответственное решение человека.
- **R4: пути отказов недостижимы или молчат.** Ошибка ffmpeg убивает выполнение до манифеста; Kokoro без
  onError; API без credential тихо деградирует (→ сделано: флаг partial); у ворот нет лимита ожидания.
- **R5: переносимость ноль.** Id credential и localhost в шаблоне, host.docker.internal, свой образ Docker.
- Блокеры для галереи n8n: Execute Command недоступен в n8n Cloud, девять таких узлов плюс свой образ =
  автоматический отказ. Жёсткие id, пути, localhost. Неавторизованный вебхук с resume-ссылками.
- Правки по объёму: часы — белые списки, onError на ffmpeg/Kokoro/sub-workflow, лимит ожидания, auth на
  /webhook/audit, $env.WEBHOOK_URL вместо localhost, pairedItem вместо индексов; дни — заменить все base64-записи
  на Convert to File → Read/Write Files, чтение на Read/Write Files + Extract from File, хранилище на Data
  Tables или Postgres, реестр по расписанию; недели — ворота на Slack/Gmail Send-and-Wait с аутентификацией,
  метки через Edit Image, видео/аудио за отдельным сервисом, ядро без Execute Command.

## 3. Нанимающий менеджер

- Первые 60 секунд: понятна только страница аудитора. Карта без README — спагетти; «recycling, three voices,
  Kokoro af_bella» ничего не говорят маркетологу; линия-образец без ворот выглядит как ловушка, которую автор
  сам поставил и сам захлопнул; три актива, три решения и один рецензент за один вечер на localhost — игрушка.
  Самый интересный блок, текст с редакторским исключением, пуст.
- Пять вопросов без ответа: кто кроме тебя проходил ворота; какой объём и задержка на воротах при 300
  креативах в день; сколько стоит прогон и кто держит инстанс; что ломалось и что поменял; смотрел ли
  юрист формулировки.
- Сигнал для роли лида операций, а не разработчика: цифры первыми (N активов, % возвратов, медиана времени
  решения, Z генераторов найдено на чужом инстансе, K непокрыты); сценарий из маркетинга героем (GPT-пост +
  ElevenLabs-озвучка, которую ворота останавливают), а не мусорные баки; однострочник «Compliance as a
  property of the line: every AI asset stops at a named human, and the auditor's page fills itself»;
  README вести со страницы аудитора и таблицы статусов, Docker и JSON в приложение для инженеров; добавить
  полстраницы «как я бы это раскатал»: кто ревьюит, эскалация, недельный отчёт, чему обучена команда.
- Две линии подавать не как два проекта, а как один тезис и два доказательства: слева черновик креативного
  конвейера как *pitch* с числом пропускной способности (300/день), справа линия AI Act как *governance*
  с числом покрытия; одна фраза-мост: карта, которая продала первую линию, теперь рисует вторую из живого
  экспорта. Pipeline Map — сноска «инструмент», не третий заголовок.

## Мой список правок

Сделано 17.09 утром (минуты): белый список расширений и фильтр shell; согласие в «Other law»; статьи 14, 12
убраны, блоки «voluntary»; вопрос «public interest»; статус внешних генераторов из решения; таймер Wait не
ворота; флаг partial у реестра; честная колонка Disclosure; уведомление рецензенту в Slack и переименование
IF в «Human approved?».

Предлагаю дальше, по порядку ценности для роли:
1. **Дни.** Хранилище вместо файлов: Data Tables n8n или Postgres, append-only журнал с хешем предыдущей
   записи. Убирает R2, R3-часть, ответ аудитору про подмену.
2. **Часы.** Ворота на Slack Send-and-Wait как основной вариант: личность рецензента из канала, а не из поля.
   Форма остаётся запасным входом.
3. **Часы.** Дипфейк по ст. 3(60): в приёме «что изображено: человек / объект / место / событие» и «создано /
   изменено»; художественный флаг; метка «AI-generated» или «AI-manipulated».
4. **Часы.** 50(3) и чат-боты: детектор узлов распознавания эмоций и чат-узлов, выход «взаимодействие с
   человеком» как отдельный класс в анализе путей.
5. **Часы.** Раскатка для команды: полстраницы «как это живёт у компании» в README, реестр по расписанию,
   недельный отчёт письмом.
6. **Дни.** Ядро без Execute Command для галереи n8n: метки через Edit Image, видео и аудио за отдельным
   сервисом, запись файлов через Convert to File.
7. **Цифры.** Две недели прогона со вторым рецензентом, отчёт с N, %, медианой. Без этого всё остальное —
   демо.
